# 股票对比可视化

当用户要求查看盘后信号、配置提醒、管理研究模型、对比 A 股，或希望按投资约束自动选股并持续更新量化组合时使用本技能。

## 输入路由

- 先区分三种模式，不得把股票对比模式的必填规则套到信号或自动选股模式：
  - 用户要求查看买入/卖出/调仓信号、邮件提醒、模型版本，或显式调用技能但没有附加参数时，使用 `signals`；只读取现有状态，不新建约束、刷新行情或运行回测。
  - 用户明确要求比较股票时，使用 `compare`；此时至少需要 2 只、最多支持 8 只股票，名称和 6 位代码可以混用。
  - 用户提供本金、期限、目标收益、回撤、止盈止损、板块或持仓数等约束时，使用 `harness` 的量化自动选股；股票列表可以为空，只要提供了至少一个板块。
- 将“激进、激进派”映射为 `aggressive`；“中立、中间、均衡、中间派”映射为 `balanced`；“保守、保守派”映射为 `conservative`。
- 用户没有说明投资态度时，使用 `balanced`，并在回复中注明采用中间派口径。
- 三种评分口径分别来自同一插件内的 `stock-compare-aggressive`、`stock-compare-balanced` 和 `stock-compare-conservative` 技能。
- 量化决策必须让用户显式选择激进、中立或保守，并分别固定为 `aggressive`、`balanced`、`conservative`；兼容接口仍可接受 `auto`，但日常页面不以系统代选覆盖用户选择。
- 三个 Skill 是稳定控制契约，市场数据不得直接改写。每个开盘日盘后更新它们读取的版本化 `ACTIVE` 在线模型、三档策略参数、基本面快照和组合研究版本；门禁失败时沿用上一活动版本。

## 专用 Python 环境

- 本技能必须通过插件根目录下的 `scripts/start_stock_compare.ps1` 启动，禁止直接使用系统 Python、Codex 自带 Python 或临时创建 HTML 页面。
- 专用环境默认为插件根目录下的 `.venv`；也可使用 Conda 环境。启动脚本以 `runtime\.venv-path` 记录的路径为准，并依次识别环境根目录的 `python.exe` 与 `Scripts\python.exe`，也允许通过环境变量 `ARGUS_STOCK_COMPARE_VENV` 显式覆盖。
- 如果专用环境不存在或依赖不完整，先运行 `scripts/setup_stock_compare_env.ps1`。该脚本默认使用清华大学 PyPI 镜像 `https://pypi.tuna.tsinghua.edu.cn/simple`；需要切换镜像时设置 `ARGUS_PIP_INDEX_URL`。
- 环境应包含受支持的 Python 3.11 或 3.12、AKShare、AKQuant、BaoStock、tdxrs、PyYAML、PyTorch、sentence-transformers 和 transformers。Qwen3 使用本地 `Qwen/Qwen3-0.6B` 官方权重；权重文件必须通过固定 SHA-256 校验。具备 NVIDIA GPU 时应安装与驱动匹配的 PyTorch CUDA 轮子；CPU 可运行但不适合作为每日训练路径。Windows 上 `tdxrs 0.6.7` 提供 Python 3.11 预编译轮子；使用 3.12 时需要本机 C++/Rust 构建工具。启动成功后，健康检查必须返回 `is_virtual_environment=true`，且 `python_executable` 指向上述专用环境；否则按启动失败处理，不得回退到其他解释器。

初始化示例：

```powershell
& "<插件根目录>\scripts\setup_stock_compare_env.ps1"
```

## 通达信行情源

- 图表行情固定使用 `ARGUS_MARKET_PROVIDER=tdx`。实时快照、分时、最近五日1分钟、原生5/15/30/60分钟和前复权日线通过 `tdxrs` 读取通达信协议；不再调用腾讯、东方财富或 BaoStock 作为在线回退。
- 120分钟由通达信60分钟线按上午、下午交易时段聚合；周K、月K、季K和年K由通达信前复权日线聚合。
- 启动脚本会检测正在运行的 `TdxW.exe` 并设置 `ARGUS_TDX_HOME`。本地 `vipdoc` 文件为空时，使用通达信公开协议节点并如实标记来源为 `tdx_public`，不得声称读取了本地文件。
- 旧来源数据只保留在 SQLite 中用于审计。图表在通达信模式下必须优先选择 `tdx_local` 或 `tdx_public` 记录，并显示实际覆盖起止时间。
- 首次对比新股票时，先同步采集通达信报价和日线以生成排序，再启动去重的后台任务，按1/5/15/30/60分钟顺序回填历史；120分钟和各日历周期随后由这些通达信数据生成。页面会自动更新，不要改用其他行情源填补等待期。
- A 股开盘日 09:30-11:30、13:00-15:00 必须每 60 秒批量刷新市场总览关注池、已确认持仓和活动候选的报价；午休与闭市后停止分钟轮询。当前查看股票的 1 分钟线按需单独刷新，日线每日由独立进程刷新；不得让逐股分钟线、日线或历史回填阻塞下一轮批量报价。页面必须重新读取 `/api/dashboard` 并显示最近同步时间，不能只重画首次载入的数据。

## 生成链接

1. 从本技能目录向上两级定位插件根目录。
2. 按输入模式运行 `scripts/start_stock_compare.ps1`：
   - 信号、通知、模型管理或空参数：不传 `-Stocks`，使用 `-View signals`。
   - 股票对比：把股票列表作为一个带引号的字符串传给 `-Stocks`，把映射后的态度传给 `-Profile`，并使用 `-View compare`。
   - 板块自动选股：不传 `-Stocks`，使用 `-View harness`。
   - 板块自动选股的新约束需要在服务就绪后登记到 `POST /api/quant/mandates`；股票可留空，板块不能为空。只打开最近结果时不得登记新约束。
3. 读取脚本输出的 JSON。只有当 `status` 为 `ready`、`url` 存在、`market_data.provider=tdx`、`concurrency.shared_service=true` 且 `concurrency.isolated_links=true` 时，才说明页面已可用。
4. 回复中直接给出 Markdown 链接：`[打开股票对比页面](脚本返回的 url)`。同时用一句话说明采用的投资态度和股票列表。

示例命令：

```powershell
& "<插件根目录>\scripts\start_stock_compare.ps1" -Stocks "贵州茅台,五粮液,宁德时代" -Profile balanced
& "<插件根目录>\scripts\start_stock_compare.ps1" -View signals
& "<插件根目录>\scripts\start_stock_compare.ps1" -View harness
```

## 模型、信号与通知

- 标准流程为 `数据接入 -> 财务/估值模型 -> 因子策略 -> 历史回测 -> 信号发布 -> 消息提醒 -> 用户手动交易`。最后一步始终在 Argus 之外由用户完成。
- 新 `ACTIVE` 组合版本可生成 `BUY / SELL / REBALANCE / HOLD`；最近交易日快照、被拒版本和未过正式门禁候选只生成 `WATCH`。同一授权书和版本只发布一次。
- 使用 `GET /api/notifications` 读取信号、订阅、SMTP 和 outbox；用户确认后才能调用信号的 `acknowledge` 或 `dismiss`，不能生成“已成交”状态。
- 邮件订阅必须由用户显式创建。默认事件为 `BUY / SELL / REBALANCE`；未启用 `ARGUS_EMAIL_SEND_ENABLED=1` 时只入 outbox。飞书和微信当前不可用，不要声称已经接通。
- 自定义财务和估值模型先通过 `POST /api/models` 创建声明式 JSON 草稿，再由另一明确的 `activate` 请求提供批准人和 `confirmed=true`。作用域优先级为个股、行业、默认。
- 不执行用户 Python、Shell、JavaScript、Excel 宏或券商代码。Excel 规则必须先转换为字段白名单内的 JSON，再经过版本、回测和人工激活。
- 详细契约见 [references/signals-and-models.md](references/signals-and-models.md)。

## 并发和多窗口

- 多个 Codex 或 ZCode 任务可以同时调用本技能。启动脚本使用跨进程互斥并复用同一个本地服务，不要因为已有任务正在使用就另起服务。
- 每次返回的 `url` 都把股票列表和投资态度保存在查询参数中，各页面互不覆盖；不要把某个任务的链接替换成其他任务的链接。
- 服务并发处理页面请求，并合并短时间内重复的行情刷新。调用方不需要等待其他任务关闭，也不要主动停止共享服务。

## 全市场研报库

- 研报库页面为本地服务地址加 `?view=reports`。用户要求查看任意股票研报时，优先在页面中按股票名称或 6 位代码严格搜索。
- 用户要求“全部历史研报入库”时，向 `/api/reports/sync/start` 发送 `POST`，JSON 为 `{"mode":"full","restart":false}`。不要把 `restart` 改为 `true`，除非用户明确要求清空进度后重跑。
- 使用 `/api/reports/sync/status` 读取总页数、已处理页数、入库条数和错误。任务采用单线程分页、逐页提交和断点续传；服务重启后自动从 `next_page` 继续。
- 用户要求暂停时，向 `/api/reports/sync/pause` 发送 `POST`。当前页写完后状态会变为 `PAUSED`，再次启动全量任务会从断点继续。
- 全量任务成功后，服务每小时检查一次当天增量；每天只成功执行一次，并对最近 7 天做重叠扫描后按原文地址去重。服务关闭期间不会采集，但下次启动会立即补做当天增量。
- 不要为任意单只股票重新抓取全市场。全量库完成后直接使用严格搜索；只有库中确实没有结果时，才使用个股研报接口补充检查。

## 代理 Harness

- Harness 是股票研究代理的持久化执行层。它负责冻结输入和业务上下文、生成受限计划、只调用允许列表内的工具、持续记录事件和工具结果、在失败后从检查点恢复，并按风险等级执行自动门禁或人工审批。
- 创建股票研判运行时调用 `POST /api/harness/runs`，例如 `{"workflow":"stock_analysis","input":{"stocks":["600519","000858"],"profile":"balanced"},"intent":"比较两只股票"}`。高级审计区可显式手动运行 `quant_portfolio`；质量巡检使用 `quality_audit`；底层三档策略实验和激活分别使用 `strategy_evolution` 与 `strategy_activation`；配置候选晋级和版本回滚分别使用 `candidate_activation` 与 `version_rollback`。
- 使用 `GET /api/harness/runs/{run_key}` 读取运行状态、增量事件、工具调用、上下文和结构化结果。服务启动只把超过四小时默认租约的陈旧 `RUNNING`/`QUEUED` 任务标为 `INTERRUPTED`，不得覆盖另一健康服务正在执行的任务；`FAILED` 或 `INTERRUPTED` 运行可通过 `/resume` 从最后一个成功工具继续，运行也可通过 `/cancel` 明确终止。
- 只读工具和内部审计写入可以自动执行；策略实验本身属于内部研究写入。策略激活、配置晋级和版本回滚属于 `CONSEQUENTIAL_WRITE`，Harness 必须进入 `WAITING_APPROVAL`。只有用户明确确认并填写处理人后，才可调用 `POST /api/harness/approvals/{approval_key}/resolve`。
- 工具允许列表不包含任意 Shell、券商连接或订单执行。持续学习工作流可以生成并评测唯一白名单文件 `runtime/app/evolvable/intraday_recipes.py` 的纯数据候选；AST 门禁禁止导入、函数调用、属性访问、文件/网络/进程/密钥和券商相关能力，且必须在数据库快照和代码副本中通过编译、全量测试、验证集改善及独立留出风险门禁后才可原子发布并保留回滚备份。
- 用户只提供本金、期限、目标收益、最大回撤、止盈止损、板块、持仓数和迭代轮数时，调用 `POST /api/quant/mandates` 登记或复用约束，再通过 `POST /api/quant/decision` 读取结果。已有匹配版本时返回最近 `ACTIVE`；首次约束或尚无匹配版本时必须立即尝试返回结果：有活动模型和已发布参考模板时返回 `SNAPSHOT`，候选流动性、技术信号和模型评分全部截断到最近一个已完成逐日评测并通过门禁的活动模型训练日；活动模型或参考模板尚未建立、但至少 420 个共同交易日的候选缓存足够时返回 `RULE_SNAPSHOT`，按走势、公告日基本面、成交活跃度和稳定性排序，并为候选计算即时多周期统计预测。`RULE_SNAPSHOT` 必须根据用户本金和最多持仓数排除已触发减仓/卖出风险的股票，再按因子、预测方向和波动形成研究权重，按 A 股整手取整后明确返回建议金额、股数和剩余现金。首屏用研究金额与现金汇总组合 P10/P50/P90 未来金额走线；单股最近 90 根日 K、预测中位线和 P10-P90 扇形区间默认收在折叠项。周期来源、样本数、P10/P25/P50/P75/P90 价格和方向统一收在“专业数据与计算依据”，数据不足的周期必须逐项说明。长周期重叠窗口可用于范围估计，但上涨参考必须按非重叠等效样本收缩，并同时展示滚动窗口数与有效段数。即时研究分配和组合同分位汇总尚未经过本组合样本外验证，不得冒充真实持仓、成交、账户盈亏、活动模型概率或收益承诺。真实持仓仅用于成本止损、账户盈亏和卖出数量，不得成为拒绝给出已经触发的标的级卖出复核的理由。财务缺失时只能标记“行情靠前，财务待补”，不得称为通过基础规则。两类快照均不得刷新数据、采集舆情、创建量化运行、训练模型或运行回测。只有连即时规则排序所需的候选缓存都不足时才显示当前无法计算，并给出缺少的数据，不得用笼统的“盘后自动补齐”代替原因。若盘后新轮次仍在运行、失败或被门禁拒绝，继续返回快照或上一 `ACTIVE`，直到新 `ACTIVE` 原子提交。`?view=harness` 的运行队列、工具调用、审批、坏案例和源码门禁收在“专业运行记录与高级设置”折叠区。

### 策略自进化

- 需要用户提供本金、期限（月）、目标收益率、最大回撤、2-8 只股票、最大同时持仓数和固定/浮动止盈方式；关注板块可选。目标收益是软目标，最大回撤是硬约束。
- `strategy_evolution` 在固定参数白名单内生成 1-20 轮组合候选，为激进、平衡、保守三档按 126 个交易日一期运行半年递推交叉验证。第一期使用冻结基线；以后每期开始前只能读取已经结束的半年结果选择参数，本期结果只能参与下一期更新；最后一期在选参后只运行一次独立留出测试。源码候选不在该工作流内处理，而由 `continuous_learning` 的隔离源码门禁单独处理；Prompt、Skill 和风险定义仍属于人工发布的控制平面，不能被行情数据静默改写。
- 组合回测使用前一日信号、下一日开盘成交，支持多次交易、换股、止损和浮动止盈。佣金最低收费、卖出印花税、滑点、整手、成交量、停牌、涨跌停近似和 T+1 必须随实验记录。
- 只有三档策略的滚动验证、最终留出风险门禁以及相对第 1 轮基线的非退化门禁全部通过，实验才可进入 `strategy_activation`；即便通过也必须等待人工批准。详细契约见 [references/harness.md](references/harness.md)。

### 量化选股与每日更新

- 用户要“给定本金、周期、止盈止损、回撤和板块后由系统选股”时，优先登记量化授权书并读取已发布策略，不要要求用户先手工确定最终股票，也不要在请求期间运行 `quant_portfolio`。候选股票可留空；板块与候选股票至少提供一项。手填股票是候选范围，不等于最终建议持仓。
- 输入包括 `capital`、`horizon_months`、`target_return_pct`、`max_drawdown_pct`、`stop_loss_pct`、`take_profit_pct`、`trailing_stop_pct`、`sectors`、可选 `stocks`、`max_candidates`、`max_positions`、`risk_profile`、`take_profit_mode`、`max_iterations`、`preference_weights`、`strategy_style` 和 `backtest_window_years`。五类关注重点为 `trend`、`fundamental`、`probability`、`liquidity`、`stability`，后端按合计 100% 归一化并写入授权书身份；同一投资约束下不同权重必须产生不同参数版本。
- 基本面是正式选股因子。历史信号只读取 `NOTICE_DATE <= signal_date` 的最新财报和 `valuation_asof <= signal_date` 的估值快照，覆盖成长、质量、现金流、安全和估值五维，禁止把后续披露用于更早日期。
- 激进、中立、保守的基本面综合信号权重分别为 25%、40%、55%；激进侧重成长，中立均衡质量/成长/现金流/安全，保守侧重安全与现金流。缺失项必须降低覆盖率并展示淘汰原因；生产基本面库建立后，不得用零值或行业均值伪造合格分。
- 每个开盘日盘后还必须刷新财报与估值快照，并基于同一收盘数据重新评测三档参数与趋势跟随、优质成长、合理价格成长、低波动、现金流估值、催化动量等细分方法，再发布版本化活动制品。页面保存的关注重点立即参与最近交易日排序，但必须标明验证状态；只有盘后滚动验证和最终留出门禁通过后才可替换正式 `ACTIVE`。
- 回测默认使用最近 3 年、约 756 个共同交易日的滚动队列；每个新交易日加入队尾，并移除窗口外最旧数据。用户可选择 1/3/5 年，1 年方案仍需额外披露指标预热和半年递推所需的更早数据。报告必须逐期列出形成参数截止日、每个 126 交易日样本外区间、当期冻结的参数版本、是否换参、收益与回撤，并把最后 126 个交易日标为只打开一次的最终独立检查。
- 自动候选池先读取通达信盘后股票主数据和行业层级，写入带来源时间戳的 SQLite 缓存，再按行情流动性、历史数据完整度筛到最多 30 只。上游不可用时只能使用已有缓存并暴露陈旧时间，不能虚构板块关系。
- 回测把用户止损、止盈和最大回撤视为不可放宽的约束，使用前一日信号和下一日开盘成交，并计入费用、滑点、整手、流动性、停牌、涨跌停近似及 T+1。预测因子必须按“先预测、后看到结果、再更新下一日”的 prequential 顺序进入历史回测，不得把未来标签用于当日信号。
- 正式 `ACTIVE` 和已评测 `SNAPSHOT` 输出应包含推荐档位、当前候选排序、股票名称与代码、五类分项和综合分、目标权重、整手股数、现金比例、止盈止损规则、独立留出集净值、最大回撤，以及投资期限内收益的 P10/P50/P90、达到目标的历史比例和亏损比例。收益区间是历史留出集净收益的区块自助估计，不是承诺。未评测 `RULE_SNAPSHOT` 输出可追溯的因子排序、缺失项、整手研究金额与股数、剩余现金、组合未来金额走线、单股多周期K线统计范围和标的级条件式买卖复核；必须保留 `positions=[]` 并将研究分配单独放入 `research_allocations`，明确它不是实际持仓且尚未经过样本外校准。
- 每次结果都要展示可信度：1 日方向准确率、AUC、Brier、概率校准、1/5/20 日前 K 名上涨命中率、样本数与 95% 区间，以及收益、年化收益、超额收益、最大回撤、Sharpe、胜率、盈亏比、换手、成本、滚动稳定性和最差窗口。必须列明回测股票、纳入/剔除原因、数据源、日期范围和逐股/板块/行情阶段拆分；缺少的指标明确写“暂无数据”，不得省略或伪造。完整报告契约见 [references/recommendation-report.md](references/recommendation-report.md)。
- 每只候选的画像至少覆盖盈利与成长、现金流与负债、估值、趋势与波动、成交活跃度、股东和管理层变动、公告事件、行业、新闻/研报/情绪与风险。每项同时报告来源、数据日期、覆盖状态和缺失原因；缺失项不得填零或用行业平均数冒充。
- 新正式版本需与上一活动版本生成逐日差异，解释持仓增减、排名变化、参数变化及其来自新行情、最新公告日基本面、模型更新还是用户参数版本。
- 自动档位先筛选样本外最大回撤与非退化门禁均通过的策略。存在 P50 达到目标的策略时返回距离目标最近的合格方案；没有达到目标但仍有风控合格策略时，明确标记 `CLOSEST_FEASIBLE` 并返回 P50 与目标差额；没有任何风控合格策略时标记 `NO_RISK_FEASIBLE`、保持 100% 现金，只展示最接近目标的研究候选，不能把它表述成可执行持仓。
- 每个工作日盘后，`continuous_learning` 会刷新日线与 1 分钟数据并聚合 5 分钟数据，采集东方财富新闻/参与度和哔哩哔哩公开元数据，结算旧预测，重训在线模型与 Qwen3 数值时序适配器，进化 5 分钟策略，并刷新所有活动量化授权书的候选排序、回测和组合版本。Qwen3 主干冻结，20 个交易日的标准化特征被映射为数值 token；只训练投影层与涨跌/收益双头。校准只能使用验证集，每个候选版本在最终留出集上只评估一次。若同一留出窗口已被用于人工调参或执行规则修复，后续结果必须标记为复核，不得再声称是全新独立样本外成绩；更高等级晋级必须等待新的滚动窗口或前向影子样本。X 只使用官方 Bearer Token；未配置时必须显示 `UNCONFIGURED`。
- `continuous_learning` 的盘后阶段是活动授权书自动刷新数据、回测并发布新组合的唯一默认路径。发布必须在同一数据库事务中归档旧 `ACTIVE` 并写入新 `ACTIVE`；事务完成前的所有读取仍返回旧版，失败、异常中断或 `REJECTED` 候选不得替换生产版本。
- 每个开盘日盘后都必须以当日完整行情评测候选模型；只有通过样本量、非退化、改善和最大回撤门禁的模型才能成为新活动模型，未通过时保留上一活动模型。停盘日或当天盘后任务尚未完成时，快照推断必须同时使用该活动模型的 `training_end` 作为行情截止日，不能混用更晚但尚未完成模型评测的数据。
- 交易日判断优先使用已缓存的官方 A 股开市日历；日历覆盖范围内缺失的工作日按休市处理，只有超出缓存覆盖时才使用工作日兜底。盘后任务若发现 `data_asof` 尚未覆盖当日，必须标记数据未完成并按受控间隔重试，不能把陈旧行情当成当日更新。Windows 任务在盘前运行一次并在 18:00 盘后运行完整回测；服务内调度器负责幂等补跑和未到齐数据重试。
- 每日还会对受控策略配方生成源码候选。只有编译、全量单元测试、验证集改善、独立留出收益非退化和最大回撤门禁全部通过才会发布；失败候选保留审计但不覆盖生产文件，隔离数据库副本在评测结束后删除。确定性的成交、费用、风险框架、Harness 核心和 Skill 文本仍由测试与人工发布保护。整个过程不连接券商、不自动下单。

## 反馈与配置演化

- 坏案例、回归评测、配置候选和不可变版本是 Harness 的反馈子系统，不等同于完整 Harness。用户指出搜索无结果、股票识别错误、排序不符合可验证标准、数据缺失、交互失败或对比异常时，将事实写入 `/api/harness/bad-cases`。
- 服务启动后的主动巡检只运行确定性探针并记录候选。直接调用 `POST /api/harness/autonomous/run` 时固定使用 `{"auto_apply":false,"stock_limit":20}`；任何候选均不得静默生效。
- 全角字符到半角字符的 NFKC 转换，以及本地股票主数据中正式名称到唯一代码的映射，可以形成确定性候选，但仍必须通过新旧版本对照评测，并经 Harness 人工审批后才能晋级。
- 股票观点和 Skill 文本不能由运行服务静默改写。评分配置候选仍需回归评测和人工批准；只有白名单内的纯策略配方可走自动源码门禁。坏案例必须包含输入、实际结果和可验证期望；配置候选必须修复目标、至少改善一例且新增退化为零。
- 每次晋级产生不可变配置版本；回滚同样需要人工确认。详细状态、请求格式和边界见 [references/harness.md](references/harness.md)。控制台地址为本地服务加 `?view=harness`。

## 边界

- 页面只做研究排序和历史回放，不连接券商、不下单、不承诺收益。
- 配置和策略源码演化都必须可审计、可复现、可回滚；任意代码修改、未测试发布和自动交易均被禁止。
- 不创建、读取或保存任何 API Key JSON 文件。
- 数据不足或脚本启动失败时，直接说明具体错误，不生成一个未经验证的链接。
- 页面中的数据日期、置信度、缺失字段和推翻条件属于结论的一部分，不要省略其风险含义。
