# Rooftop

本地 A 股研究台 · 投资研究助手 · 可选邮件日报

当前版本：**1.1.2**。

Rooftop 是一个本地运行、面向 A 股的量化研究与盘后信号系统，由两位开发者与 Codex 协作构建。输入本金、期限、关注板块和风险条件，即可查看相对优选的股票、逐项筛选理由，以及独立计算的资金方案；也可以比较 2–8 家公司，查看历史走势与未来情景区间，订阅大盘和关注公司的邮件简报。

当前版本重点：**可调筛选宽松度、预算内研究排名、不强制平均分配、左历史右预测的图表，以及启动后持续核对行情、收盘后更新策略。** 研究名单、筛选通过状态和组合验证结果分别展示，方便看清“值得继续研究”与“当前条件下可以分配资金”的区别。

Rooftop **不连接券商、不提交订单、不承诺收益**。所有金额、股数和价格区间都是研究输出；只有用户导入真实持仓后，系统才会计算真实账户口径的成本、盈亏和可卖数量。

## 从这里开始

| 想做什么 | 页面入口 | 得到什么 |
|---|---|---|
| 用自然语言提出研究问题 | 投资研究助手 | 条件解析、本地工具结果、证据解释和追问；需登录 Codex CLI |
| 按本金和风险条件筛选股票 | 股票推荐 | 预算内相对优选、筛选不足说明、独立资金方案及历史验证 |
| 比较几家公司 | 股票对比 | 2–8 只股票的资料、评分与风险比较 |
| 收到昨天大盘或关注公司的简报 | 信号中心 | 可选邮件内容、发送时间、预览、发送记录和收件确认 |
| 查看行情或管理自己的股票 | 市场总览 | 行情图表；只有自行确认导入后才显示真实持仓 |

首次使用先完成[安装](#6-安装)，再运行 `./scripts/start_stock_compare.ps1 -View harness`，打开脚本输出的 `url`，即可进入股票推荐。无需先导入持仓，也无需先配置邮箱；邮件配置完成后才会外发。全新安装需要先积累行情和历史数据，页面会显示数据是否足够用于研究。

## 1. 当前能力

- 股票对比：激进、均衡、保守三种研究口径，综合技术面、基本面、估值、催化剂和下行风险。
- 相对优选：对所选板块中历史数据齐备的候选评分，优先展示本金可覆盖最小买入单位的股票，逐只保留未通过条件的说明。
- 可调筛选：评分偏好、风险档位和 0–100 筛选宽松度分别控制排序、风险参数和入选门槛。
- 资金分配：按本金、仓位限制和配置的买入单位计算研究金额、股数与现金余量；最多持仓数是数量上限，金额可以不同。默认买入单位为 100 股，特殊交易规则仍需复核。
- 未来情景：单股图左侧为历史收盘价，右侧为已检验期限的中位数与区间；主图聚焦 P25—P75 核心区间，较宽区间及更长期限可展开，长期历史基准另表披露。
- 回测：按时间顺序进行滚动验证和最终留出评估，使用下一交易日开盘或下一根完成 K 线开盘模拟成交。
- 交易约束：佣金、最低佣金、卖出印花税、滑点、整手、成交量参与上限、停牌、涨跌停近似和 T+1。
- 财务与估值：公告日可得数据、每日估值快照、声明式自定义模型、版本化激活范围和缺失覆盖率。
- 信号中心：`BUY / SELL / REBALANCE / WATCH`，支持确认、忽略、版本追踪和失效条件。
- 邮件订阅：选择昨日大盘总结、指定公司简报和研究信号，设置北京时间发送时间；支持预览、按日期补发、去重和失败重试。默认不外发。
- 投资研究助手：通过已登录的 Codex CLI 调用本地数值研究工具，展示证据、支持追问和 JSON 导出。
- 真实持仓：首次使用为空；关注名单和研究分配不会写入账户。无持仓时不展示市值、盈亏或持仓风险卡片。
- 行情同步：服务启动立即核对关注池报价，此后每 60 秒核对，收盘和休市继续运行；当前分钟 K 线自动刷新，交易日 15:01 起安排盘后数据检查与策略更新。
- 多源资料：通达信公开行情、本地通达信文件、AKShare、BaoStock，以及可选的 Bilibili、X API、SEC EDGAR。
- 搜索：本地严格匹配；可选 Qwen3 Embedding 语义检索。
- 持续学习：在线概率模型、可选 Qwen3 数值适配器、5 分钟策略演化、组合策略演化和受控源码候选。
- Harness：固定工作流规划、持久化步骤、工具白名单、心跳、租约、人工审批、失败恢复和版本回滚。

## 2. 系统边界

| 能力 | 是否支持 | 说明 |
|---|---:|---|
| 股票研究、回测、情景区间 | 是 | 结果保留数据时间、模型版本和证据覆盖 |
| 研究资金分配 | 是 | 不代表真实持仓或成交 |
| 导入真实持仓 | 是 | 仅用于成本、盈亏和卖出复核；不会连接券商 |
| 邮件提醒 | 是 | 默认 dry-run；显式启用后才发送 |
| 自动下单 | 否 | 代码和数据库均不包含订单执行链路 |
| 收益保证 | 否 | 目标收益用于比较目标差距，属于软目标；不会为了达到目标而编造结果 |
| 核心数值计算 | 本地 | 规则、概率模型、回测和可选本地 Qwen 模型 |
| Codex 研究助手 | 可选 | 使用本机登录的 Codex CLI；研究问题与精选证据会发送到该账户对应的服务 |

## 4. 模型到底用了什么

Rooftop 不是“让一个大模型直接猜股价”。不同任务使用不同模型，并且每个模型都必须保留数据时间和验证状态。

| 任务 | 当前模型 | 默认启用 | 作用 |
|---|---|---:|---|
| 股票对比 | 确定性风险档位规则 + 历史趋势回测 | 是 | 激进/均衡/保守口径排序 |
| 即时约束选股 | 多因子确定性评分 | 是 | 技术、财务、概率、流动性、稳定性综合排序 |
| 多周期价格区间 | 历史相似状态加权分布 + split conformal 校准 | 是 | 1日、1周、1月、1季、1年 P10/P50/P90 |
| 每日上涨概率 | 在线逻辑回归概率模型 | 是 | 仅用已实现结果逐日更新系数 |
| 财务/估值模型 | 声明式 JSON 评分模型 | 是 | 按默认、行业、个股作用域计算维度分数 |
| 语义搜索 | `Qwen/Qwen3-Embedding-0.6B`，512 维 | 可选 | 中文金融资料向量检索 |
| 深度时序研究 | `Qwen/Qwen3-0.6B` 数值 token 适配器 | 可选 | 下一交易日方向概率和预期收益 |
| 5 分钟策略 | 参数白名单内的规则策略演化 | 是 | 已完成 5 分钟 K 线、下一根开盘模拟 |
| Harness 规划 | `bounded-domain-planner` 确定性规划器 | 是 | 将固定意图映射到允许工具 |
| 自然语言研究 | 已登录的 Codex CLI | 可选 | 解析研究需求、调用本地工具、组织解释；不替代数值计算和验证门禁 |

### 在线概率模型

“在线”指新样本到来后逐步更新参数，不是必须联网，也不是聊天大模型。逻辑回归把加权特征映射为 0–1 的方向概率；它预测上涨可能性，不直接给出保证成交的价格或保证收益。

特征为 `bias`、5 日动量、20 日动量、5/20 日均线差、20 日波动率、成交量 z-score、公开资料情绪和市场 5 日动量。模型先预测，再在真实结果出现后更新；同一天的结果不会用于同一天预测。版本门禁比较方向准确率、Brier 分数、收益误差、策略回报和最大回撤。

### Qwen3 数值适配器

深度研究使用本地 `Qwen/Qwen3-0.6B` 主干，将标准化数值特征投影为输入 embedding，并增加方向分类头和收益回归头。权重不在本仓库中；运行时校验 `model.safetensors` 大小和 SHA-256。设备由 `ARGUS_QWEN3_DEVICE=auto|cpu|cuda` 控制。没有本地权重时系统降级，不会调用在线 API。

### 多周期区间与预测图

个股主图优先显示最近一个通过检验期限的 P25—P75 核心区间，列出金额、中位数、历史实测覆盖率和检验样本数。更长期限及 P10—P90 宽区间可展开查看。核心区间的检验未通过时不展示较窄带；未检验的期限不会混入校准曲线。更短期限或较窄分位范围只改变观察范围，不代表模型预测准确率提高。

| 图上位置 | 表示什么 | 阅读方式 |
|---|---|---|
| 左侧历史线 | 已有的历史收盘价 | 主图按预测期限选择最近 30–90 个交易日；展开时使用最近 90 个交易日，数据不足时按已有记录显示 |
| 中间分界线 | 数据截止日与参考收盘价 | 历史和未来从同一个参考价格衔接 |
| 右侧中位线 | 已检验期限的校准中位数 | 只连接实际期限节点，不代表逐日价格预测 |
| 右侧区间色带 | 核心 P25—P75 或展开后的 P10—P90 | 结合页面列出的历史实测覆盖率和检验样本数判断，而不是把分位范围当作准确率 |

左右共用价格纵轴，但**时间横轴分段缩放**，为历史与未来分别留出可读空间；不能凭线条的视觉斜率直接比较两侧涨跌速度。中位线和色带边缘只连接已有节点，不生成虚构的每日波动或每日区间。没有通过检验的未来节点时，仅保留历史图和缺失说明；长期历史基准放在专业表格中，不混入校准预测曲线。

分钟周期只作为描述性上下文。日线周期必须经过按时间排序的 walk-forward、条件相似样本分布、split conformal 校准和相对历史基准的非退化门禁。没有足够样本或没有证据优于基准时，前端必须明确披露，不能把宽泛区间包装成高置信预测。

更完整的模型输入、输出、训练、门禁与降级规则见 [模型栈说明](runtime/docs/MODEL_STACK.md)。

## 5. 环境要求

- Windows 10/11 或 Windows Server。
- PowerShell 5.1+。
- Python 3.11 或 3.12；仓库的 Windows CI 使用 3.12。
- 建议至少 8 GB 内存。
- 投资研究助手另需可用且已登录的 Codex CLI；股票对比、数值推荐和邮件日报可独立使用。
- Node.js 22 可运行前端回归测试；普通 Web 页面无需 npm 安装或构建。
- 本地 Qwen 模型可使用 CPU；训练建议 NVIDIA GPU。RTX 50 系显卡需要匹配的 PyTorch CUDA 构建。
- 通达信客户端不是必需项；免费公开节点可提供行情，但稳定性、历史深度和授权边界由上游决定。

## 6. 安装

```powershell
git clone https://github.com/tianyuzong/rooftop.git
Set-Location rooftop

$env:ARGUS_STOCK_COMPARE_VENV = "C:\venvs\argus-stock-comparison"
./scripts/setup_stock_compare_env.ps1
```

安装脚本会创建或复用独立环境，安装行情、研究和语义检索依赖，并在 `runtime/.venv-path` 写入本机环境路径。该文件已被 Git 忽略。

若使用自定义 PyPI 镜像：

```powershell
$env:ARGUS_PIP_INDEX_URL = "https://pypi.org/simple"
./scripts/setup_stock_compare_env.ps1
```

### Zcode 接入

插件同时提供 `.zcode-plugin/plugin.json`、Zcode Skill 和斜杠命令。首次使用或源码更新后运行：

```powershell
./scripts/install_zcode_integration.ps1 -Force
./scripts/zcode_cli.ps1 skills list --json
./scripts/zcode_cli.ps1 commands list --json
```

Zcode 中的主入口是 `/rooftop-stock`；原来的 `/argus-stock` 作为兼容别名保留。两者都支持无参数查看信号、传入 2-8 只股票进行对比，或传入本金、风险和板块条件自动选股。

`zcode_cli.ps1` 会自动查找正在运行的 Zcode，包括安装在非系统盘的版本；Node.js 不在 `PATH` 时也会尝试使用 Codex 自带运行时。其他机器可通过 `ZCODE_CLI_PATH` 和 `ZCODE_NODE_PATH` 显式指定路径。

## 7. 启动

### 投资研究助手

这是原“Codex 研究员”入口的新名称。先确保本机可运行 Codex CLI，并完成 `codex login`，然后打开助手：

```powershell
./scripts/start_stock_compare.ps1 -View agent
```

描述本金、期限、回撤限制和关注股票/板块。Codex 解析约束，调用本地数值研究工具，引用证据解释结果；页面展示价格情景、研究分配、服务状态和学习评测。支持保留上下文的追问、取消、重试和 JSON 导出。

需求及精选研究证据会发送至本机登录的 Codex 账户，访问令牌不会发送给模型。本机通过 `127.0.0.1`、`localhost` 或 `[::1]` 直接打开页面时自动连接；远程登录框支持输入令牌或选择令牌文件。

日线计算会检查历史缺口及复权价格断层，仅使用最近连续数据段，保留原始记录并披露排除原因。预测区分样本外校准与历史基准情景。后台监测器自动重启已经退出的组件；长任务不会仅因观察超时而重启。

持续学习包括预测结算、在线模型与本地 Qwen 训练、策略参数演化，以及受限源码候选的隔离测试、样本外评测和回滚。候选不通过门槛时保留现有版本；这不代表修改 Codex 自身模型权重，也不保证预测一定改善。

### 信号中心

```powershell
./scripts/start_stock_compare.ps1 -View signals
```

### 股票对比

```powershell
./scripts/start_stock_compare.ps1 `
  -View compare `
  -Stocks "贵州茅台,五粮液,宁德时代" `

```

`Profile` 支持 `aggressive / balanced / conservative` 及对应中文别名。

### 约束选股

```powershell
./scripts/start_stock_compare.ps1 -View harness
```

填写本金、期限、板块、风险档位、最多持仓数和筛选宽松度，点击“按这些条件查看推荐”。页面会直接定位到“本次结论”，先展示可研究的公司和逐项理由；若数据不足，原因也会显示在同一区域。

#### 三组设置分别改变什么

| 设置 | 选项 | 实际作用 |
|---|---|---|
| 评分偏好 | 偏走势 / 均衡 / 偏财务与稳定 | 改变技术、财务、概率、成交活跃度和稳定性在综合分中的权重 |
| 风险档位 | 激进 / 中立 / 保守 | 改变策略与风险参数，包括正式分配的单只仓位上限 |
| 筛选宽松度 | 0–100，界面初始值 50 | 放宽上涨概率、均线、动量和基本面分数门槛 |

评分预设的五项权重如下；专业模式也可调整各项，系统按比例归一化。修改后点击“保存并用于股票推荐”才用于后端重算。

| 评分偏好 | 走势 | 财务 | 上涨概率 | 成交活跃度 | 稳定性 |
|---|---:|---:|---:|---:|---:|
| 偏走势 | 30% | 20% | 25% | 15% | 10% |
| 均衡 | 25% | 30% | 20% | 10% | 15% |
| 偏财务与稳定 | 15% | 40% | 15% | 5% | 25% |

这三组设置可以独立组合，例如“偏走势 + 保守风险 + 宽松度 50”。提高宽松度不意味着自动提高仓位。

#### 筛选宽松度

0 保留原门槛，50 适度放宽，100 使用当前实现允许的最大放宽。相对当前策略原门槛，各项按宽松度线性调整：

| 调整项 | 0 | 50 | 100 |
|---|---:|---:|---:|
| 上涨概率门槛下调 | 0 | 7.5 个百分点 | 15 个百分点 |
| 价格、短期均线低于长期均线的容忍幅度 | 0 | 5% | 10% |
| 动量下跌的容忍幅度 | 0 | 10% | 20% |
| 基本面最低分下调 | 0 | 0.15 分 | 0.30 分 |

概率门槛最低为 0；基本面调整使用模型分数单位。财务覆盖要求、历史数据要求、本金、最大回撤、止损和仓位上限保持各自约束，缺失数据不会因宽松度提高而变成合格证据。

调整滑块后点击“按这些条件查看推荐”生效。即时筛选和盘后回测使用同一套宽松度计算；新条件会重新区分验证状态，不会借用旧版评估宣称已经通过。API 字段为 `screening_relaxation`，旧请求未传时默认为 0，以兼容原有行为。

#### 先看研究名单，再看资金方案

即时研究排名覆盖所选板块中历史数据齐备的候选，不再先截取成交额前 30 只；实际范围取决于本地板块成员与历史覆盖，并非自动扫描全部 A 股。盘后完整回测仍保留独立的候选计算预算。

| 结果层次 | 你会看到什么 | 代表什么 |
|---|---|---|
| 相对优选 | 本金可覆盖的候选优先；筛选通过者在前，其余按综合分排列；可展开不受本金限制的排名 | 即使没有公司全部过关，仍可比较有数据的候选及其不足 |
| 筛选状态 | 当前规则是否通过，以及走势、概率、财务等未过条件 | 仅说明当前入选规则，不能代替完整组合回测 |
| 资金方案与风控评估 | 独立展开查看正式仓位或试探方案、股数、现金和阻碍分配的原因 | 受本金、仓位、交易单位和验证条件约束，可能暂无可投入组合 |

研究卡片上的最小买入金额只用于判断本金能否覆盖，**不是已经分配的仓位**，不能把多只股票的这些金额直接相加当作组合。没有可投入组合，也不等于没有值得继续研究的候选；没有有效行情和历史证据时仍会明确显示不足。

股票推荐不受开盘时间限制：收盘、周末和节假日均可修改条件，读取最近有效交易日的缓存结果，并查看其数据日期。推荐表单先显示，专业后台状态只在展开时加载；后台训练或状态读取失败不会阻塞推荐页。刷新超时会说明原因并保留同一组条件上次成功读取的结果，也可手动重试。没有足够行情时会明确说明，不会编造推荐。本机和 Rooftop 服务仍需保持运行。

| 页面状态 | 含义 |
|---|---|
| 最新正式结果 / `ACTIVE` | 已发布版本；仍需查看数据日期、历史评估和本次资金分配 |
| 最近交易日结果 / `SNAPSHOT` | 使用已评测模型与缓存数据，当前组合仍待盘后验证 |
| 即时预测结果 / `RULE_SNAPSHOT` | 使用本地缓存规则和区间研究，不等于完整组合回测 |
| 暂无可投入组合 | 可能已有研究排名，但受到买入单位、仓位上限或验证条件限制；查看资金方案中的具体原因 |
| 数据不足或读取失败 | 显示缺失数据或错误原因，不以成功提示代替结果 |

“最多持有”只限制股票数量，不要求平均分配。正式分配按综合评分、波动和整手约束分别计算，单只仓位上限独立取决于风险档位（激进 60%、中立 45%、保守 35%），不会由最大持有数量推导。允许各只金额不同，余款保留为现金；即时研究排名也不要求凑满持仓上限。规则快照或试探方案可以使用更低的仓位限制，以页面实际披露为准。旧版组合重新分配后作为待盘后验证的快照显示。

例如：本金 10 万元、激进档、最多持有 6 只，正式分配的单只上限为 6 万元，而不是 `10 万 ÷ 6`。假设参考价 412.22 元、买入单位 100 股，在其他条件允许时，100 股对应 41,222 元；忽略费用时余款为 58,778 元。这只是上限与买入单位的算例，不代表系统一定分配该金额。若最小买入金额超过当前方案的风控上限，页面会解释原因。

没有股票投入时不展示股票组合收益曲线。参考策略的历史收益、回撤和模拟统计不代表这笔未分配资金的预期收益；研究数量也不会自动变成真实持仓。

启动脚本输出 JSON，`url` 为页面地址。未指定端口时会选择可用端口，并且只复用 Python 环境、插件版本、运行时代码指纹和数据湖都一致的健康服务。

### 指定数据目录

```powershell
$env:ARGUS_DATA_LAKE = "C:\RooftopData\data_lake"
./scripts/start_stock_compare.ps1 -View signals
```

不要把数据湖放进 Git 仓库。它可能包含行情原始响应、研报正文、邮箱地址、模型输出和审计日志。

## 8. 最小 API 示例

默认本机服务不需要令牌。假设地址是 `http://127.0.0.1:8765`：

```powershell
$base = "http://127.0.0.1:8765"
Invoke-RestMethod "$base/api/health"
Invoke-RestMethod "$base/api/market-sync"
Invoke-RestMethod "$base/api/market/quotes?symbols=600519,000858,300750"
```

登记研究条件：

```powershell
$body = @{
  input = @{
    name = "白酒与新能源"
    capital = 100000
    horizon_months = 12
    target_return_pct = 20
    max_drawdown_pct = 15
    stop_loss_pct = 8
    take_profit_pct = 20
    trailing_stop_pct = 8
    sectors = @("白酒", "新能源")
    max_candidates = 12
    max_positions = 8
    max_iterations = 10
    risk_profile = "balanced"
    screening_relaxation = 50
    take_profit_mode = "trailing"
  }
} | ConvertTo-Json -Depth 6

Invoke-RestMethod `
  -Method Post `
  -Uri "$base/api/quant/mandates" `
  -ContentType "application/json" `
  -Body $body
```

`screening_relaxation` 为 0–100，省略时为 0；`max_positions` 是持仓数量上限，`max_candidates` 控制完整回测的候选预算，不应理解为即时研究名单必定只有这么多只。`/api/market-sync` 可查看真实采集状态，行情同步时间与策略的数据日期分别记录。

接口不会在请求线程中启动训练或完整回测。它读取已发布版本或可用缓存；缓存日期更新而正式模型仍旧时，可返回明确标记的 `RULE_SNAPSHOT`。没有活动版本时尝试 `SNAPSHOT` 或规则结果，数据不足则返回具体原因。完整评测留给盘后任务。

全部 GET/POST 路由、请求字段、状态码和副作用见 [API 参考](runtime/docs/API_REFERENCE.md)。

## 10. 数据源与刷新节奏

### 行情

- 默认在线源：通达信公开 TCP 节点。分钟报价和近期分钟 K 线使用 `pytdx` 公共行情握手；其他历史采集保留 `tdxrs`。
- 本地补充：`ARGUS_TDX_HOME` 指向通达信目录；本地文件为空时只报告不可用。
- `mixed` 模式保留腾讯/东方财富/BaoStock 兼容采集路径，但默认 `tdx` 模式不会在线调用旧行情源。
- QMT/miniQMT 和 Futu OpenD 当前只做只读就绪探测，不包含交易方法。

### 刷新

默认开启后台刷新；本机及服务保持运行时，各项节奏如下：

| 对象 | 默认节奏 | 实际更新内容 |
|---|---|---|
| 通达信报价采集 | 启动立即核对，此后每 60 秒 | 核对关注池报价；收盘、周末和休市继续核对，价格可能不变 |
| 页面当前时间 | 每秒 | 本机时钟，不表示收到新行情 |
| 页面同步状态 | 每 5 秒 | 读取后台真实状态；最近整批同步时间只在整批成功后推进 |
| 行情与查看中的分钟 K 线 | 每 60 秒，切回页面立即刷新 | 读取最新缓存，并由后台补齐当前分钟图；开盘有新数据时继续更新 |
| 日线检查 | 每 6 小时 | 检查并更新日线 |
| 历史检查 | 每 24 小时 | 检查历史缺口并回填 |
| 研报与公告 | 每小时 | 检查当天增量 |
| 盘后学习与策略 | 交易日 15:01 起安排 | 检查收盘数据、评测策略和更新推荐；数据未齐或失败时重试，法定休市日跳过 |

15:01 是盘后任务开始调度的时间，不是保证完成的时间。任务排队、上游数据未到齐或评测仍在运行时，页面保留上一版有效结果并显示更新状态。收盘价核对成功也不会直接把旧策略的数据日期改成今天。

分钟报价按每批最多 60 只请求，区分同代码的沪深市场，ETF 报价按三位小数归一化。顶部同步状态在所有页面每 5 秒重新读取，只有整批成功且未超过 120 秒才显示正常；部分返回、失败或过期会提示重试。采集时间是收到通达信报价的时间，不冒充交易所成交时间。

HTTP 行情接口只读 SQLite。即使上游节点超时，页面仍可显示最后可信快照并标记时间。

## 11. 邮件订阅与日报

### 在页面完成配置

1. 打开“信号中心”，填写订阅名称和收件邮箱。
2. 勾选邮件内容，可选一项或多项：
   - **昨日大盘总结**：当日指数行情和有来源的收评、新闻。
   - **关注公司情况**：输入股票名称或六位代码，用逗号分隔，例如 `宁德时代，688012`；包含该日行情、截至该日已公告财报、当日相关报道。最多 20 只。
   - **研究信号**：额外接收买入、卖出、调仓等提示，可设置事件类型和最低置信度。
3. 设置每日发送时间，默认 **08:30，北京时间**，保存订阅。关注名单不会写入真实持仓。
4. 展开“配置发件邮箱”，填写发件地址、SMTP 服务器、加密方式、端口和邮箱服务商提供的授权码，勾选启用发送，再点击“保存并验证连接”。
5. 先用“预览日报”检查所选日期和内容，再使用“测试收件”或“发送这一天的日报”。实际在邮箱中看到邮件后，点击对应记录的“我已收到”。

163 邮箱需先开启 SMTP，并使用授权码。常用连接方式为 SSL / 465 或 STARTTLS / 587；以发件邮箱服务商的配置为准。授权码只在本机配置，不要写进仓库或研究问题。

### 日报日期与数据范围

- 默认总结北京时间的**前一个自然日**。周末或休市日没有行情时会标注缺失，不会悄悄改成上一交易日。
- 可选择历史日期预览或补发；同一订阅、同一报告日期使用一个去重键，重复点击不会重复发出已发送的日报。
- 日报读取本机已保存的资料，明确列出来源、数据日期和缺失项；不会用未来数据、演示行情或成本价补足报告。
- “未检索到当日报道”仅表示本地没有匹配资料，不代表公司当天没有事件。当前日报是确定性资料简报，不会额外调用大模型生成结论。
- 本机和 Rooftop 服务必须保持运行。当天在计划时间之后启动会尝试补排昨天日报；停机多日的更早报告需按日期手动处理。

### 如何判断真的收到邮件

| 记录状态 | 表示什么 |
|---|---|
| 尚未配置 / 未启用 | 订阅可以保存，邮件不会外发 |
| 等待发送 | 邮件已进入本地队列，尚未被发信服务器接受 |
| 重试中 / 失败 | 发送发生错误；自动退避重试最多 5 次，也可检查配置后手动重试 |
| 服务器已接受 | SMTP 服务端接受了邮件，不等于已经进入收件箱 |
| 已确认收到 | 用户在邮箱中看到邮件后，主动确认收件 |
| 已取消 | 订阅内容更新或停用后，相关未发送邮件被取消 |

SMTP 连接验证只验证登录与连通性，不会证明邮箱投递成功。收件服务商仍可能延迟、拒收或放入垃圾邮件；请用实际收件完成验证。系统区分连接成功、服务器接受和用户确认，不能承诺必达。

### 通过环境变量配置

未使用页面保存设置时，也可以在启动服务的 PowerShell 会话中配置：

```powershell
$env:ARGUS_SMTP_HOST = "smtp.example.com"
$env:ARGUS_SMTP_PORT = "465"
$env:ARGUS_SMTP_SECURITY = "ssl"
$env:ARGUS_SMTP_USER = "research@example.com"
# ARGUS_SMTP_PASSWORD 由本机安全配置提供，不要把真实值写入脚本或提交。
$env:ARGUS_ALERT_TO = "research@example.com"
$env:ARGUS_EMAIL_SEND_ENABLED = "1"
```

页面设置位于 `ARGUS_DATA_LAKE/secrets/email_settings.json`，不在 SQLite 中保存授权码明文。DPAPI 密文依赖保存时的 Windows 账户；更换电脑或运行账户后应重新配置。详情见[信号与通知](runtime/docs/SIGNALS_AND_NOTIFICATIONS.md)及[配置参考](runtime/docs/CONFIGURATION.md)。

## 12. 远程部署

默认只绑定 `127.0.0.1`。绑定非回环地址时必须提供令牌文件：

```powershell
./scripts/start_stock_compare.ps1 `
  -View signals `
  -BindAddress 0.0.0.0 `
  -PublicHost argus.example.com `
  -PublicScheme https `
  -TokenFile C:\ArgusSecrets\remote.token `
  -AllowedHosts "argus.example.com" `
  -AllowedOrigins "https://argus.example.com"
```

远程 API 使用 `X-Argus-Token` 请求头。所有 API 有按客户端 IP 的内存限流；修改请求还校验 Origin，并写入 `api_audit_log`。生产环境仍必须使用 HTTPS 反向代理、防火墙来源限制、最小权限账户、独立数据盘和定期备份。

即使启用了远程令牌，本机直接打开 `http://127.0.0.1:8765` 也无需手动输入。页面请求带有本机连接标记，服务端同时核验实际连接来源、回环 Host、端口及同源信息；转发请求仍须令牌。若设置了 Host/Origin 白名单，请包含要使用的本机地址。反向代理应保留转发标头，不能将远程请求伪装成本机直连。

详见 [安全部署](runtime/docs/SECURITY_DEPLOYMENT.md)。

## 16. 可信度与已知限制

- 免费行情可能延迟、缺失、限流或改变协议；页面时间戳比“实时”字样更可信。
- 研究范围受本地板块成员、名称映射和历史覆盖限制，不能把候选排名理解成已比较全部 A 股或所有概念板块。提高宽松度不能补齐缺失的历史、财报或行业映射。
- 买入单位默认按 100 股配置，涨跌停模型以前收盘价为基准近似；尚未完整覆盖各板块、ST 和特殊交易状态。
- 历史回测不能证明未来有效；重复使用过的留出窗口不会继续宣称“未触碰”。
- `RULE_SNAPSHOT` 是缓存数据上的即时研究，不等同于完整组合样本外评测。
- 分位区间来自条件历史分布与校准，须结合样本外实测覆盖率阅读；样本不足会扩大区间或降级。图上期限节点的连线不代表逐日价格预测。
- 财务数据按公告日可得性对齐，缺失字段会降低覆盖率而不是用未来数据补齐。
- Bilibili 浏览器会话、X API、SEC、SMTP 和本地模型均为可选配置，不配置时必须显式显示未就绪或降级。
- 数据和模型许可证由使用者负责核对；商用前必须确认上游授权。

## 18. 常见问题

**“偏走势 / 均衡 / 偏财务与稳定”和“激进 / 中立 / 保守”有区别吗？**

有。前者改变综合评分权重，后者改变策略与仓位风险参数，可以独立选择。筛选宽松度是第三个设置，只调整入选信号的门槛。保存偏好或重新提交推荐条件后才会用于重算；候选数据有限时，不同设置也可能得到相同名单。

**没有股票全部通过筛选，还能看到推荐吗？**

只要所选范围内有可评分的历史数据，就会列出相对优选并说明不足，优先展示本金可覆盖的候选。可提高宽松度比较更多入选者，但研究排名不会自动变成已验证组合。如果历史不足或板块没有匹配数据，仍需先补齐数据，不能靠宽松度生成证据。

**“已读取正式结果”，为什么没有买入金额？**

正式版本说明模型记录已经发布，不保证当前本金和仓位约束允许分配。先查看研究名单，再展开“资金方案与风控评估”，检查最小买入金额、单只仓位上限及验证状态。最多持有 6 只也不表示必须平均分成 6 份。

**为什么每分钟刷新了，价格或“数据截至”还是没变？**

当前时间、最近整批行情同步时间和策略数据日期是三件事。收盘后继续核对报价，收盘价本身可能不变；整批失败时同步时间也不会伪装更新。策略日期要等盘后数据到齐并完成评测后才推进，刷新页面不会重跑完整模型。

**预测线为什么接近直线？**

图左侧是已有走势，右侧连接参考价和通过检验的未来期限节点。只有一个未来节点，或中位变化很小时，连线就会接近直线；这不表示未来每天横盘。请结合中位变化金额、区间范围和实测覆盖率阅读，系统不会为了让曲线好看而添加不存在的逐日预测。

**我没有股票，为什么以前显示两笔 ETF？**

旧版曾把本地历史示例显示为账户内容。现在真实账户只展示用户确认导入的持仓；首次使用为空，关注股票与研究组合独立管理。旧预设假设不再生成，已知示例会归档。

**保存了订阅，为什么没收到邮件？**

依次检查发件服务是否配置并启用、订阅是否启用、发送记录的状态，以及邮箱的垃圾邮件文件夹。仅保存订阅或验证 SMTP 登录都不代表已经投递成功。

**数据、模型或 Codex 暂时不可用怎么办？**

查看页面时间戳、缺失原因和 `/api/services` 状态。缓存可继续用于明确标记的研究；没有有效证据时显示不可用。后台监测器可以恢复已退出的组件，不能自动解决上游授权、停机断网或缺失模型权重。
